## 二、考官意图与核心逻辑链（大白话拆解）

### 1. Workflow 与 LLM 确定性边界（Q02）
- **考官想验证什么**：鉴别你是不是“什么事都一股脑抛给大模型”，能不能分清代码工作流和 AI 推理的界线。
- **大白话逻辑链**：黄金法则是**“能用确定性 if-else 写死的事，绝不浪费钱交给大模型猜”**。比如校验参数格式、鉴权、按路由推流、审批落库全归确定性代码工作流；只有意图归纳、模糊信息提取才交给大模型。每多一次模型调用，时延、成本和不可控错误率就叠乘一层。

### 2. Tool Calling 服务端分发与区分「Prompt 烂 vs 模型笨」（Q03）
- **考官想验证什么**：危险操作防误触发 + Bad Case 定位是否科学。
- **大白话逻辑链**：工具必须走**服务端统一分发**（模型只发意向和参数，服务端校验权限、热更新工具版本、写审计），删库或转账类破坏性工具绝不能直接放开给模型自动执行，必须让前端弹确认。排查模型为什么调错工具，靠**控制变量对比大一档模型** + **看错误是不是集中在某一个工具**：如果更强模型也错、且 80% 错在同一个工具，大概率是那个工具说明书（Schema 描述）写得含糊不清；换强模型立马变对才是模型能力门槛。

### 3. 模型不听话 5 档修法与「反思污染上下文」（Q04–Q05）
- **考官想验证什么**：调不听指令时，有没有从便宜到贵的排障顺序，以及知不知道把错题原样塞回上下文反而越改越糊涂。
- **大白话逻辑链**：治理不听话从便宜到贵排五档：**流程硬约束（框架里写死必须先查再答）→ 后处理清洗（剥掉多余代码块）→ 加 1~3 条典型示例 → 调低温度参数 → 最后才微调**。注意“自我反思”如果把大段“我刚才犯错了、对不起”原样留进主对话，模型下一轮就会变得唯唯诺诺甚至不断道歉复读，必须把反思总结放到草稿区只回写精炼结论。

### 4. Redis 信号题与低代码对比（Q09、Q11–Q14）
- **考官想验证什么**：Redis 在 Agent 系统里用来存什么（短期对话状态、缓存、Stream 轻量消息），以及对比字节系自家 Coze 与代码编排的适用边界。
