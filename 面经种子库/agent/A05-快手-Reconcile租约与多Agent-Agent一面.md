## 二、考官意图与核心逻辑链（大白话拆解）

### 1. Reconcile + Lease 租约 + Fencing Token 防「僵尸写」（Q01–Q08）
- **考官想验证什么**：这是极高水平的分布式底层拷打——当一个干活的 Agent Worker 突然卡死又奇迹般醒来时，怎么防止它把新接任 Worker 刚写好的结果覆盖掉。
- **大白话逻辑链**：
  1. **Reconcile（状态对账恢复）**：就像恒温空调，不去背“刚才开到几档”，而是不断对比“房间现在温度”和“目标温度”的差值来推下一步动作；所以机器崩了重启，重算一遍差值就能接着干，前提是每步动作重复做也不出错。
  2. **Lease（定时租约）**：工人干活前先领一块“15 秒有效工牌”，每 5 秒续一次期；一旦机器断电崩溃，不用等它主动交工牌，15 秒一到工牌自动作废，新工人就能接手。
  3. **Fencing Token（单调递增门禁令牌）**：万一老工人只是堵在路上（比如长 GC 卡顿或断网 20 秒），新工人领到第 `2` 号工牌上岗后，老工人带着过期的 `1` 号令牌醒来继续往数据库写数据就出事故了！**所以每次领租约都要把门禁编号严格加 1，而且老工人每次去仓库（数据库/存储层）写数据时必须把门禁号递给仓库管理员校验——仓库看到已经收过 `2` 号，直接把更小的 `1` 号写入拦截拒掉。** 这也回答了第 6 题：门禁号不能只放在外面的租约表里当摆设，必须跟着每次写入交到存储端点强校验才算真正闭环。

### 2. 拆穿「伪多 Agent」与对照评测门槛（Q09–Q12）
- **考官想验证什么**：有没有跟风上多 Agent 却压根没跟单 Agent 跑过同一批题的对照实验。
- **大白话逻辑链**：用固定任务集（涵盖简单单跳、复杂多跳和必须拒绝的负例），同模型同工具分别跑单、多架构，连跑多次看均值和方差，综合对比成功率、耗时、Token 花费和失败分类；拿不出对比数据就诚实承认没做过，硬编一追即溃。

### 3. 目录化 `AGENTS.md`/Skill 安全与会话恢复污染（Q15–Q20）
- **考官想验证什么**：配置/技能目录和历史会话落盘后，会带来哪些越权泄露和指令注入漏洞。
- **大白话逻辑链**：把规则文件和 Skill 放进代码目录，就等于开放了提示词入口——别人仓库里恶意塞一段指令就可能诱骗 Agent 泄露密钥，所以加载 Skill 要限死可信目录、校验防路径穿越，配置目录严格只读；恢复跨天新会话不能直接把老消息原封不动塞进来（工具和代码可能都变了，老假设会误导模型还白烧 Token），应该压缩提炼成“当前目标+已确认事实+待办”的结构化摘要再开新局。
