## 二、考官意图与核心逻辑链（大白话拆解）

### 1. 场景题：禁用 MQ 时，如何只靠数据库搭一套可靠的异步系统（Q02）
- **考官想验证什么**：去掉现成队列轮子后，你懂不懂“任务不丢、多机不抢重、状态可查、积压能监控”这四个异步系统底层本质。
- **大白话逻辑链**：把任务请求想象成医院抽血叫号单：请求一进来，先在数据库任务表插一张`待处理`工单再秒回单号（落盘保不丢）；后台多台处理机器一起去数据库抢单时，用数据库提供的行锁跳过指令（只抢没人锁住的下一条，避免撞车），干完改成`成功`或失败记重试次数；前端拿单号轮询或者靠推送拿结果。最重要的是主动补一句：**这套单库轮询方案 QPS 有天花板、只适合量小图省事，量上来还是得换专用队列**——考官最想听的就是你懂方案边界。

### 2. Agent 开发与传统后端开发的本质区别，以及 POST 幂等（Q03、Q11–Q13）
- **考官想验证什么**：大模型岗也要懂 HTTP 限流重试（`429 Too Many Requests`）与幂等保护，还要分得清确定性代码和概率性 Agent 研发范式的差异。
- **大白话逻辑链**：传统后端是“输入确定、路径确定、输出必须唯一”；Agent 是“输入是自然语言、中间要根据推理循环动态选工具、结果有概率波动”，所以开发重心从“写死流程”转向了“管上下文、建工具护栏、做流式恢复与评测回归”。而面对模型或客户端因为遇到 `429` 限流反复重发 `POST` 请求时，必须让调用方带唯一请求标识，由服务端建唯一约束或状态机锁住只办一次。

### 3. 计算机地基与 Redis/MQ 积压斜率告警（Q04–Q22）
- **考官想验证什么**：火山引擎极重操作系统（进程切换为什么比线程贵？因为要切页表刷 TLB 缓存）、网络协议、Redis 单/多线程真相（命令执行主线程单线程，网络 I/O 和惰性释放用多线程）及 MQ 积压监控（按积压增长斜率告警比死阈值更准）。
