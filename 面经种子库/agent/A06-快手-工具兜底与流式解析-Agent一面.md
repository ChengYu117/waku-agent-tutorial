## 二、考官意图与核心逻辑链（大白话拆解）

### 1. 工具失败「分类处理 + 五层兜底」（Q1）
- **考官想验证什么**：考官绝不接受“失败了就统一重试 3 次”这种粗糙答案，他在查你会不会分清错误性质、防死循环烧钱。
- **大白话逻辑链**：快递送不出去要看情况：门牌临时修路（网络超时/限流/5xx）过几秒再跑一趟（指数退避重试）；填错了手机号（参数不合法）把报错原因写回给模型让它重填；写着“禁止入内”（权限不足/资源不存在）直接打回绝不白费力气重试。所有写工具都要带“唯一业务单号（幂等键）”，重试次数用光了走降级模板兜底，最外层加上**步数、耗时、Token 预算三重熔断电闸**，防止 Agent 卡在错误反馈里无限鬼打墙。

### 2. 上下文三档压缩与「金额/单号永不进摘要」（Q3）
- **考官想验证什么**：当对话越来越长时，怎么省 Token 又不把致命细节弄丢。
- **大白话逻辑链**：压缩分三档，从便宜到重：① 只保留最近几轮对话的滑动窗口；② 把早期聊天滚动揉成一段摘要；③ 把用户偏好和核心事实抽成结构化档案存到库里按需召回。**这里有一条铁律：订单号、金额、日期、硬性约束绝不能交由大模型写进自然语言摘要！** 因为摘要一概括，模型很容易把 `10086` 略掉或改写数字，必须作为独立结构化字段永远贴在醒目位置。

### 3. 三层输出质量衡量与红蓝对抗（Q4、Q6）
- **考官想验证什么**：有没有建立起“规则卡底线 → 模型评软质量 → 人工校准+反派攻击测试”的闭环。

### 4. 手撕：流式 JSON 解析状态机（Q5）
- **考官想验证什么**：大模型流式吐字（SSE / TCP 分块）时，一句完整工具调用 JSON 可能被劈成两半（半包），或者两句挤在一个包里（粘包），能不能写一段不靠“按回车换行切分”的字符扫描机。
- **大白话逻辑链**：准备一个蓄水池缓冲区 `buf`，用两个小开关盯住每个字符：一是“当前是不是正走在双引号字符串里面（还要记住反斜杠转义，免得字符串里出现引号闹乌龙）”，二是“外面大括号和方括号嵌了几层 `depth`”。每当不在字符串里且括号层数正好归零，说明拼出了一整块合法 JSON，立刻切出来消费；流结束还要清空尾巴，并限制单包最大长度防内存被打爆。

| 本场高频考点 | Twenty CRM 对应机制（大白话） | 证据状态 | 面试建议 |
