## 二、考官意图与核心逻辑链（大白话拆解）

### 1. Agent 断点续跑、隔离防串位与「确认后必走代码」（Q03–Q09）
- **考官想验证什么**：你在业务流程里敢不敢把决定权交给大模型，以及长会话下怎么防断电、防串味、防乱认消息。
- **大白话逻辑链**：断点续跑就像游戏自动存档（checkpoint）——每一步跑完把输入摘要和结果落库，重启后已成功的步直接拿存档跳过。多用户隔离靠“租户+用户+会话ID”三道锁死；防模型把第 2 条消息看成第 1 条，不是在 Prompt 里求模型“注意别混”，而是每条消息编有序号、返回时校验引用 ID 是否属于当前会话。最关键的是**用户点“确认提交”那一刻，必须立刻切回确定性后端代码去校验和写库，绝不让大模型临门一脚把参数改歪**。

### 2. binlog 对账、MQ 积压雪崩与「影子写」灰度（Q11–Q30）
- **考官想验证什么**：高可用老兵才会踩的坑——大流量下“对账系统自己误判把下游打爆”，以及资金/库存类逻辑能不能直接双跑。
- **大白话逻辑链**：如果某天突然批量新开一万家门店导致 MQ 积压延迟了 5 分钟，对账程序如果不先看队列积压水位，就会以为“两边账对不上”，一口气发起上万次错误补偿把系统直接干趴下——所以对账前必须先检查消费延迟，积压高时自动降级成只报警不自动补偿。另外，读和算价可以双跑对比，但**涉及扣钱、扣国补额度的写操作只能写进“影子库/影子账”，额度只能在唯一权威主链路扣减**。

### 3. 本地消息表与 AI Coding 工程 SOP（Q37–Q40）
- **考官想验证什么**：业务写库和发消息怎么捆在一起不丢，以及你平时用 AI 写代码是盲目抽卡还是有工程规范。
- **大白话逻辑链**：本地消息表就是“把要发的消息和业务数据写进同一个数据库事务”，成功就一起成功，再让后台扫表工人把消息投出去，保证至少送到一次。用 AI Coding 也一样：先人写清楚一页纸规格和验收条件（SPEC + 规则文件），再让 AI 小步写、跑测试验收，人负责把控边界。

## 三、与 Twenty CRM 项目的映射与边界

| 本场高频考点 | Twenty CRM 对应机制（大白话） | 证据状态 | 面试建议 |

| Agent 断点续跑与流式防丢 | Agent 支持按步骤记录与前端流式恢复，HITL 人工暂停可挂起等待用户恢复后继续 | `有证据` | 对应“步骤存盘+人工确认后确定性执行” |
