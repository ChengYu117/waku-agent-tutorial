## 一、本场真实面试题清单（忠于原帖）

4. LLM 返回的 tool call 格式不合法或参数类型不对，你的系统怎么处理？有没有做校验和重试？重试几次？

## 二、考官意图与核心逻辑链（大白话拆解）

### 1. 工具返回 50MB 爆窗口与 Harness 工程落地（Q02–Q08、Q18–Q21）
- **考官想验证什么**：直接淘汰只会喊“让 AI 总结一下”的选手，专门考核**模型之外的运行时骨架（Harness）**到底能不能扛住真实生产体积和脏数据。
- **大白话逻辑链**：第 8 题堪称灵魂一问！工具吐出 50MB 数据，如果指望让大模型先读完再做摘要，窗口当场就炸了。真正的工程做法像图书馆借大部头档案：**50MB 原始数据压根不放进大模型对话里，而是直接落盘到文件或对象存储，只给大模型一张“小卡片”（文件路径/引用 ID + 行数或字段结构摘要 + 分页或关键词查询入口）**，模型真要看哪一段再自己带着偏移量来查。至于 Harness，就是这套包围在模型外面的“工装护具”：管工具注册发现、上下文管理、沙箱隔离、失败修复、心跳续跑与评测，Orchestrator 只是它里面专门做步骤调度的那一层。

### 2. 长任务可靠性：断点续跑、路径震荡与多 Agent 冲突（Q09–Q13）
- **考官想验证什么**：Agent 跑 20 步中途崩了或原地打转怎么办。
- **大白话逻辑链**：断点续跑靠数据库记录“任务表 + 步骤表”，每次迁移带版本号防并发写乱，已完成的步骤直接复用存盘结果，不再重复扣费或执行副作用；路径震荡（同一个报错连试五次）靠记录已失败轨迹注入提示，连续失败两次自动换思路或降权屏蔽该工具。

### 3. 安全防线（注入/越权/沙箱）、百工具治理与并发估算（Q25–Q31）
- **考官想验证什么**：工程算账能力 + 安全红线意识。
- **大白话逻辑链**：遇到 100 个工具不能全塞进提示词，要靠工具注册中心按类别和场景“渐进式暴露”；防注入不能靠对模型说“请忽略坏人”，而是在工具执行网关层把权限、危险操作拦截死，把生成的代码关进无外网权限的隔离沙箱里跑。日 10 万次并发估算则用“排队论（Little's Law）”算平均占用时长：5 次工具 1 秒 + 推理时间 = 单任务占用几秒，乘以每秒到达率再留足余量。

## 三、与 Twenty CRM 项目的映射与边界

| 本场高频考点 | Twenty CRM 对应机制（大白话） | 证据状态 | 面试建议 |
| :--- | :--- | :--- | :--- |
| **第 8 题：工具返回 50MB 不进上下文的工程落地** | Twenty 内置 `ToolOutputSpillService`（工具输出溢写机制）与结果精简压缩器：大返回值自动落磁盘文件存储，只把文件句柄和摘要留给模型按需查询 | `有证据` | **超级王牌题！** 与第 8 题要求严丝合缝，面试必讲 |
| Harness 核心模块（主循环、修复参数、取消、沙箱） | Twenty 完整具备 Agent 循环（Prompt Cache `sortKeysDeeply`、硬步数 300 步上限、`repairToolCall` 格式自愈）、代码沙箱、SSRF 拦截和 Redis 取消订阅 | `有证据` | 对照第 18 题系统输出你对 Harness 工程的理解 |
| 100+ 工具治理与 MCP 注册 | 工具注册中心按角色渐进发现、按需加载，结合 MCP 三种接入模式 | `有证据` | 直接对接 Q28–Q29 |
| 长期记忆冲突处理、多 Agent 文件并发改写、Vector RAG/RRF | Twenty 仅有单会话 90% 上下文裁剪，不包含跨会话长期语义记忆、多 Agent 并行改代码与向量 RAG | `无证据` | 诚实标为无证据，按工程架构原则拆解场景回答 |
