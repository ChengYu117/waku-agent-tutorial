## 二、考官意图与核心逻辑链（大白话拆解）

### 1. RAG 切块不均治理与 RRF 融合直觉（Q05–Q08）
- **考官想验证什么**：按 Markdown 标题切块是新手最常见动作，考官追问“一个章节五千字、一个章节十个字怎么办”，以及两路分数尺子不一样怎么合并排序。
- **大白话逻辑链**：
  - **切块不均**：“结构 + 长度”双保险递归切分！先按大标题分，碰到几千字的超长块就顺着段落、句子继续往下细分到几百 Token 左右，碰到一句话的超短块就和相邻块粘起来；相邻块边缘留一点重叠（Overlap），或者用“小块负责精准搜出来，命中后把所在大段落整段拎给模型”的父子回填法。
  - **RRF（倒数排名融合）**：向量搜索打分在 `0~1` 之间，关键词 BM25 打分可能跑到 `18.5`，两把尺子刻度完全不同硬加权很容易翻车。RRF 干脆**不看分数只看排名**：`1 / (60 + 名次)` 把几路排名前列的文档顺手叠加起来，既稳又抗极端高分干扰。

### 2. Plan vs MCP 权责分层、服务端权限与「怎么避免天天弹窗确认」（Q09–Q12）
- **考官想验证什么**：极实用！很多产品上了人工确认（HITL）后，用户点个查询都要连弹五次确认框直接被烦死——考官想看你会不会分级治理。
- **大白话逻辑链**：MCP 解决“工具从哪接进来”（统一协议跨应用复用），Plan 解决“复杂多步任务先排计划再挨步执行”。**权限控制绝不能靠提示词祈祷，必须在服务端死守四关**：工具白名单、请求自动绑死租户/用户且限制查询行数（严禁放模型乱写裸 SQL）、按数据所有者鉴权、全链路审计。至于**如何不一直弹人工确认**，按风险分层：**只读、可逆、仅限本人数据全自动放行**；只有**改库、发钱、外发消息、改权限**等高风险才弹确认，并且用“差异预览卡片”合并一次确认，低风险习惯动作首次确认后记住规则免打扰。

### 3. 后端基础与 Redis 宕机恢复（Q14–Q19）
- **考官想验证什么**：从并发容器/锁/内存泄漏（如 ThreadLocal 不清理、静态集合只增不减），到 Redis 单机持久化恢复（混合持久化）与机房主备故障切换的取舍（诚实承认异步主从切换存在丢数据窗口）。
